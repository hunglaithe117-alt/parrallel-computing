# Cross-language benchmark results

Generated by `bench/run_all.sh` (via `bench/aggregate.py`) purely from the captured stdout `BENCH,` lines in `results/raw/`. The merged data is `results/results.csv`. No number in this report is hand-written.

## Machine and methodology

- CPU: Intel Core i5-14400 — 6 P-cores (CPU 0-11 including SMT siblings), 4 E-cores (CPU 12-15), 1 NUMA node. AVX2 + FMA3; **no AVX-512**.
- Caches: L1d 48 KiB per P-core, L2 ~1.25 MiB per P-core, L3 20 MiB shared; 64 B cache lines.
- Governor `powersave` with turbo on: pinned medians still vary ~10-15% run to run.
- `THREADS=12` (`taskset -c 0-11`, P-cores with SMT); `OMP_NUM_THREADS`, `RAYON_NUM_THREADS`, and `GOMAXPROCS` are all set to 12. Single-thread rows pin `taskset -c 2` (one P-core, SMT sibling idle).
- `REPS=7` timed repetitions per row. Each benchmark warms up once before timing and reports the median.
- Merge precedence (contract v2.1): single-thread variant rows are taken only from the ST pass, multi-thread rows only from the MT pass.
- **Noise / tie rule:** differences under ~15% are ties; a row is flagged `(tie)` when it is within that margin of the fastest row in its class for that kernel. Ordering inside the noise band is not treated as an effect.
- `scalar` is a within-language reference, not a cross-language baseline (contract v2.1 N1); the cross-language table compares time only.
- Comparison and tie decisions use the reported **median**; `min` is an advisory stability diagnostic printed to stderr and is not consumed for ranking (contract v2.1 measurement rule 7).

## 3. Excluded / not cross-language-comparable

- `mandelbrot` — per-language `MAX_ITER`/viewport differ (contract v2.1 N2); the rendered work is not the same across languages. Captured `n`: C++=786,432, Rust=786,432.
- `false_sharing_adjacent` — cross-language absolute times are not comparable: C++ uses a `volatile` load/store while Go must use `atomic.AddInt64` (a locked read-modify-write), so the per-increment cost differs; compare within a language. Captured `n`: C++=24,000,000, Go=24,000,000.
- `false_sharing_padded` — cross-language absolute times are not comparable: C++ uses a `volatile` load/store while Go must use `atomic.AddInt64` (a locked read-modify-write), so the per-increment cost differs; compare within a language. Captured `n`: C++=24,000,000, Go=24,000,000.
